Мета: Розробити інтерактивну Kanban-дошку для управління завданнями. Завдання має продемонструвати вміння працювати з бібліотекою Material UI (MUI), логікою роутингу в React, навички адаптивної верстки та створення чистого, візуально привабливого інтерфейсу з використанням AI-інструментів.

##### **Загальні вимоги до даних та стану**

- Дані: Усі дані мають бути виключно моковими (статичні mock-дані, які ініціалізуються в коді).
- Стан (State Management): Не потрібно використовувати Redux чи інші зовнішні стейт-менеджери (Zustand, MobX тощо). Для управління глобальним станом можна (і рекомендується) використовувати стандартний React Context.

##### **Технологічний стек**

- Бібліотека/Фреймворк: React (Vite або Next.js).
- UI-компоненти: Material UI (MUI).
- Роутинг: React Router v6.
- Іконки: MUI Icons (або Lucide React / FontAwesome за вибором).

##### Функціональні вимоги та структура проєкту

Застосунок має складатися з двох основних екранів із використанням динамічного роутингу.

###### Екран 1: Kanban-дошка (Маршрут: /)

Головна сторінка — це інтерактивний робочий простір, оформлений як дошка завдань із сайдбаром (боковим меню) або хедером.

1. Колонки: Три обов'язкові колонки: Todo (Треба зробити), In Progress (У процесі), Done (Виконано).
2. Картки завдань: Кожна картка повинна містити:
   - Назву та короткий опис завдання.
   - Пріоритет: High, Medium, Low.
   - Дедлайн (дату завершення).
   - Аватарку або ім'я відповідального (mock-зображення або текст).
3. Інтерактивність (Переміщення): Можливість переносити картку між колонками. Можна реалізувати за допомогою drag-n-drop або спрощеного керування інтерфейсом (кнопки чи інтерактивне меню перенесення на самій картці). Зміна статусу картки повинна оновлювати загальний стан.
4. Перехід до деталей: При кліку на заголовок або саму картку має відбуватися перехід на сторінку детальної інформації про це завдання.

###### Екран 2: Деталі завдання (Маршрут: /task/:id)

Сторінка з розширеною інформацією про конкретне завдання, яка отримує актуальні дані за його ID.

1. Кнопка «Назад»: Повернення на головну сторінку дошки.
2. Редагування інформації про завдання:
   - Назва та опис: Можливість редагувати назву та детальний опис завдання (UX-паттерн на вибір).
   - Відповідальний: Можливість змінити відповідальну особу для цього завдання (вибір зі списку доступних mock-користувачів).
3. Підзадачі: Чек-ліст підзадач (із можливістю відмічати виконані пункти) та теги.
4. Історія або Коментарі: Реалізуй блок історії змін або секцію коментарів, обравши найбільш відповідні елементи інтерфейсу для відображення хронології або списку повідомлень.

##### Додатковий функціонал (Буде перевагою)

Описаний вище функціонал є базовим мінімумом завдання. Якщо ти маєш бажання продемонструвати свої навички детальніше, реалізація додаткових можливостей буде великим плюсом.

##### Дизайн-вимоги (UI/UX Focus)

Це завдання має високий фокус на твої дизайн-скіли та вміння самостійно підбирати та кастомізувати компоненти:

- Кастомізація теми (ThemeProvider): Налаштуй власну колірну палітру, радіуси закруглень, шрифти та тіні через тему MUI.
- Адаптивність (Responsive Layout): Сплануй відображення дошки на мобільних пристроях.
- Увага до деталей: Використовуй сітку та гнучкі контейнери для точних відступів. Налаштуй hover-ефекти для карток та кнопок.

- Вимога: У файлі README.md додай короткий опис (2–3 речення) про свій досвід роботи з ШІ під час виконання цього завдання. Напиши, які інструменти ти використовував і в яких задачах вони тобі найбільше допомогли (написання структури, стилізація чи генерація логіки переміщення карток).
